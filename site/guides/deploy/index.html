How to deploy a GitHub website on an Android phone

Deploy a website from GitHub to an old Android phone with Homedroid. Enter the repository and build commands, follow the deployment log, then use a deploy hook to publish later pushes.

Before you start

  • A running Homedroid server, internet access and a repository that builds with a supported runtime.
  • A free port at or above 1024. For CI or GitHub webhooks, the runner or GitHub must be able to reach the phone through the access route you set up.

How to deploy a GitHub website on an Android phone: step by step

  1. Create the deployment

    Open Deployments → New deployment. Select From Git. Enter Name, Port, Repository URL and Branch.

  2. Set the runtime and commands

    Choose Runtime and enter the project’s Build command, Start command and Environment variables as needed. Select Create to start deployment.

  3. Save the one-time secrets

    Copy the Deploy token and GitHub webhook secret to a safe place when shown. They are shown once; you can replace them from the deployment’s Deploy hooks tab.

  4. Check the build and pipeline

    Open the deployment and follow its log. The Pipelines tab shows step results and output. Define any checks your project needs before relying on an automatic deployment.

  5. Connect GitHub pushes

    Open Deploy hooks to find the webhook address. In the GitHub repository, add a webhook with that URL, application/json, the saved webhook secret and push events. Pushes to the configured branch redeploy it.

  6. Test a change

    Push a small change, watch the deployment finish, then open the site at its port or configured domain. For a CI script, the token-authenticated deploy hook with ?wait=1 waits for the result.

Good to know and troubleshooting

  • The Web hosting estimate below covers the web server; your build tools and running application need additional memory and CPU.
  • A pipeline step that fails stops the deployment and leaves the previous version running. Check the failed step’s output before retrying.
  • Redeploy when the branch changes polls every five minutes; a GitHub webhook is a separate trigger. Private Tailscale access works for a connected CI runner, but a GitHub webhook needs a publicly reachable endpoint.
