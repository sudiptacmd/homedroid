How to run a local AI model on an Android phone

Run a local AI model on an Android phone with Homedroid’s AI page. Download a GGUF model, choose it under Model to run and chat in the dashboard, or connect another app to the OpenAI-compatible API.

Before you start

  • A supported 64-bit phone, free storage for a model and enough available RAM. A phone with 6 GB or more gives you more room alongside other services.
  • A running Homedroid server and internet for the runtime and model downloads. No cloud account is needed for local inference.

How to run a local AI model on an Android phone: step by step

  1. Install the local runtime

    Enable AI in Modules and open AI. Under On this phone, select Install if llama.cpp is not installed yet. If the page says local models are unsupported, this build cannot run them on that phone.

  2. Download a model

    Choose a model from the catalog and select Download. Start with a small model that fits the phone. You can also supply a GGUF download URL or upload a .gguf file to AI models in Files.

  3. Choose what runs

    Under Model to run, select the downloaded file. Choose Context and CPU threads, leaving conservative settings for the first attempt, then Save. Wait for Ready.

  4. Try local chat

    Choose the model under On this phone in the chat model picker. Send a short prompt and watch the phone’s memory and temperature while it answers.

  5. Connect another app

    Scroll to Use from other apps. Copy the API address and connection details shown there into an OpenAI-compatible client. Use the model identifier shown by Homedroid.

Typical memory and CPU

These are the estimates shown by Homedroid, from its module resource data. Memory is resident process memory; CPU describes use while busy. Actual use depends on the phone and workload.

Good to know and troubleshooting

  • A larger context also needs memory. If the model repeatedly crashes, try a smaller model or context and inspect Logs.
  • The current page offers Run on and Benchmark to compare supported CPU/GPU paths. GPU availability depends on the phone and runtime; do not assume it will be faster.
  • Cloud services are optional and send messages to their provider. Review the fallback setting if you want requests to stay local when the phone cannot answer.
