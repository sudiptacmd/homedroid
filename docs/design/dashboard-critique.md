# Dashboard UI/UX audit

Reviewed the complete original dashboard (3,109 lines), its four Node test suites, and the Kotlin handlers. Locations below refer to original selectors/functions rather than unstable line numbers. Priority: P0 blocks essential use; P1 materially impairs use; P2 usability/consistency; P3 refinement. No P0 found.

| Priority | Area / location | Finding | Concrete fix |
| --- | --- | --- | --- |
| P1 | Navigation: `.nav`, `route`, `refresh` | Twelve ungrouped destinations make scanning difficult; adding eight more will overwhelm the list. Routing requires edits to multiple conditionals. | Group by task; use a page loader registry; document a section + nav item + loader convention. Reserve future destinations in comments instead of dead links. |
| P1 | Connections: `renderSsh`, `renderOverview`, `GUIDES` | SSH commands claim port 8022 even when the phone uses another port. Settings lacks the supported port and DNS controls. | Read selected-phone settings, use its SSH port throughout; expose validated port and DNS fields with actionable help and inline server errors. |
| P1 | Accessibility: `.switch`, `.guide-dots`, `.btn.sm`, `.seg` | Controls are 8–38px wide/high, too small for touch. | Maintain compact desktop controls and at least 44px mobile hit areas, including switches and step navigation. |
| P1 | Accessibility: `drawFiles`, `.ftable thead`, `.crumbs` | Directory links without href and clickable table headers are unavailable to keyboard users. The sort listener selects the first table on the page, which is now Network. | Use focusable link semantics and keyboard activation; scope sorting to `#fBox`; expose `aria-sort`. |
| P1 | Errors: `refresh`, `noteNodeError` | Failures on the local phone disappear silently, leaving stale numbers or blank pages that look current. | Persistent status banner with escaped message and Retry; retain last successful data and clear the banner on recovery. |
| P1 | Contrast: `.toast.bad`, `.btn.danger.solid`, `.live-badge` | Dark-theme danger `#f87171` paired with white is approximately 2.77:1. Inactive switches and input boundaries lack 3:1 contrast. | Separate semantic foreground from solid fill, use dark text on pastel danger in dark mode, and strengthen interactive borders. Verify token pairs numerically in both themes. |
| P2 | Shell: `.shell`, `.top`, `.nodesel` | Desktop has no top bar or compact sidebar mode. Device context is buried in navigation; long nav overflows short screens. | Persistent context bar, scrollable grouped navigation, remembered desktop collapse, retain tested modal mobile drawer. |
| P2 | Hierarchy: `.page-head`, `h2`, `.stat`, `.mod` | Every page is similarly flat; uppercase secondary headings compete with badges and helper text. | Larger page titles, quieter sentence-case section headings, consistent card padding and primary-action placement, summary strip on Overview. |
| P2 | Typography and spacing: stylesheet and inline styles | Repeated fractional font sizes and scattered 6/10/14/18px values have no explicit scale. Dense technical copy is hard to scan. | System sans with a modular type scale, 4px space tokens, bundled mono for code, explicit title/body/helper roles. Normalize shared components first. |
| P2 | Theme: `applyTheme`, `:root` | Existing system/manual theme works, but tokens are duplicated and a saved theme is applied late. Semantic scales are incomplete. | Keep the persisted auto/light/dark choice, add neutral/accent/semantic aliases and elevation/motion tokens; apply saved choice before painting. |
| P2 | Components: `modCard`, `.mod-foot`, `.item` | Destructive actions crowd routine ones, and installed apps lack Update. Cards vary in density. | Shared action footer rhythm, secondary Update action, quiet destructive actions, consistent status badges and row dividers. |
| P2 | Responsive: `.grid`, `.aiCatalog .item`, `.top`, dialogs | 300px minimum tracks can overflow narrow layouts; AI model rows and cluster tables need deliberate wrapping/scrolling. | Clamp track minima to available width, wrap dense rows, contain table scrolling, allow device picker to shrink, test 360/390px widths. |
| P2 | Dialogs and menus: `ask`, `openMenu`, dialog elements | Native modal focus handling is useful, but dialogs lack accessible names and menus do not restore trigger focus. | Label every dialog; restore menu focus on Escape, add Home/End navigation, retain native dialog Escape and focus trap. |
| P2 | Empty/loading states: `renderOverview`, `drawFiles`, page loaders | Some initial pages are blank and empty folders offer drag-only instructions. | Lightweight loading status, skeletons for metrics, explicit upload/module CTAs, retry states. No endless animation under reduced motion. |
| P2 | Microcopy: page subtitles, Settings, module status | “Nothing you don't use runs” and long multi-clause subtitles make scanning harder; DNS failures have no remedy in UI. | Concise task descriptions; describe DNS as a fix for install lookup errors, with empty = automatic. Preserve security/privacy guidance. |
| P2 | Efficiency: navigation and commands | No quick way to jump between pages or start frequent tasks. | Ctrl/Cmd+K command dialog with filtered destinations and safe actions, arrow navigation, Enter, Escape, and visible trigger. |
| P3 | Perceived performance: `setHTML`, polling, graphs | Existing visible-page polling, unchanged-markup checks and lazy terminal loading are good. Metric cards still rebuild on every sample. | Preserve polling cadence and checks, update stat tiles independently, prevent stale refresh errors from overwriting newer page state; avoid blur and heavy effects. |
| P3 | Dated patterns: uppercase headings, initial-letter avatars, guide dots | Generic avatars and compressed uppercase labels make this feel like a utility panel. Tiny guide dots hide step purpose. | Restrained graphite/indigo palette, precise borders, balanced typography, icon treatment and accessible step controls. Keep imagery out of an operational console. |

## Implementation boundaries

Keep all existing IDs, API routes, module behaviors and marker comments. Native dialogs and the tested mobile drawer remain the accessibility foundation. Future pages (Databases, Domains, DDNS, Firewall, Request logs, MCP, Desktop & MacroPads, Pipelines) are reserved extension slots, not working features. No external dependencies or assets are added to the dashboard.

## Customization addendum

- **Layouts** (Sidebar, Rail, Top bar, Split, Focus, Tablet/Kiosk), **13 themes** (each AA-checked numerically in `tests/dashboard-prefs.test.cjs`), font families (system stacks plus bundled JetBrains Mono; any installed font by name), density, corners, shadows and CSS-only backgrounds are all driven by attributes on `<html>`; there is no per-theme JavaScript.
- **Known limits**: the Embedded app widget needs `frame-src` in the phone's Content-Security-Policy (Dashboard.kt), otherwise the frame is blocked and the widget shows an "open in new tab" link. Rail has tooltips but no flyout groups. Lower text brightness is a uniform black overlay rather than per-token colours.
- **Persistence**: `GET/PUT /api/ui/prefs`, cached in `localStorage` (`hd.prefs`); older phones without the endpoint fall back to the cache.
- Screenshots: `docs/design/screens/` (`layout-*`, `theme-*`, `font-*`, `customize-*`, `overview-*`, `widgets-edit-desktop`, `saver-kiosk`); regenerate with `tests/dashboard-mock/shots.cjs` and `visual-check.cjs`.
